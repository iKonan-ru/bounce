# Bounce

Производство песен в одном месте: проекты, этапы каждой песни от наброска до мастера, заметки с
картинками и аудио, тексты песен. Приложение (PWA) для телефона, планшета и компьютера, сервер -
PocketBase.

## Как устроено

- Пользователей заводит главный (is_admin). Вход - логин, пароль и код из
  приложения-аутентификатора (TOTP); пока 2FA не подключена, правила PocketBase не отдают данных.
- Проект создаёт любой пользователь и выбирает участников из заведённых. Песни, шаблон этапов и
  заметки живут внутри проекта и видны только его владельцу и участникам. Новый проект пустой:
  этапы новых песен задаются в его настройках.
- Заметки (текст, картинки до 20 МБ, аудио до 200 МБ) есть у проекта, у песни и у этапа; раздел
  "Все заметки" ищет по всем сразу. Файлы закрыты: ссылка работает только с токеном участника.
- У песни несколько обложек, одна из них основная; у проекта - картинка-аватар.
- Резервную копию (база, учётные записи, файлы) главный скачивает и восстанавливает сам в
  разделе "Резервная копия"; автоматических копий нет.
- Темы светлая и тёмная (палитра "Пульт"), по умолчанию как в системе.

## Стек

| Часть      | Что                                                                           |
| ---------- | ----------------------------------------------------------------------------- |
| Интерфейс  | React 19, TypeScript (строгий), Vite 8, TanStack Router и Query               |
| Компоненты | shadcn/ui (Radix), Tailwind CSS 4, шрифт Onest                                |
| PWA        | vite-plugin-pwa: manifest, service worker, установка на главный экран         |
| Сервер     | PocketBase 0.40 (официальный бинарник): база, вход, realtime, правила доступа |
| Схема      | JS-миграции в `pocketbase/pb_migrations`, типы - `pnpm typegen`               |
| Проверки   | Biome, Vitest (в том числе правила доступа на настоящем PocketBase)           |
| Выкладка   | Docker-образ, Caddy через `/etc/caddy/sites`                    |

## Структура

```
src/
  components/      экранные компоненты; ui/ - компоненты shadcn
  lib/             PocketBase, типы, запросы, логика песен и этапов
  pages/           экраны
  router.tsx       маршруты
pocketbase/
  pb_migrations/   схема и настройки PocketBase
  pb_hooks/        хуки: 2FA, резервная копия, команда bounce-admin
  VERSION          версия PocketBase для разработки и образа
tests/             тесты Vitest
deploy/            compose.yml и сайт Caddy для сервера
tools/             PocketBase для разработки, выкладка
```

## Разработка

Нужны Node.js 22+ и pnpm (`corepack enable`).

```
pnpm install
tools/pocketbase.sh bounce-admin <логин> <пароль> <имя>   # главный пользователь
tools/pocketbase.sh          # PocketBase на 127.0.0.1:8090, скачивается при первом запуске
pnpm dev                     # интерфейс на http://localhost:5173
```

При первом входе приложение попросит подключить 2FA. Остальных пользователей главный заводит
в профиле, раздел "Пользователи". Админка PocketBase (http://localhost:5173/_/) - для
суперпользователя: `tools/pocketbase.sh superuser upsert <почта> <пароль>`.

Схема менялась без переноса данных: если `pocketbase/pb_data` остался от первой версии каркаса,
удалите его перед запуском.

- `pnpm check` - типы, Biome и тесты.
- `pnpm typegen` - типы коллекций в `src/lib/pb-types.ts` после правки схемы (нужен запущенный
  PocketBase и `.env` по образцу `.env.example`).
- Новая миграция: файл `pocketbase/pb_migrations/<unix-время>_<что>.js`, применяется при запуске
  PocketBase.

## Выкладка

Приложение живёт на сервере с Docker и Caddy: контейнер в сети
`caddy`, HTTPS выдаёт Caddy.

```
tools/deploy.sh             # выложить последний коммит и дождаться ответа
tools/deploy.sh nowait      # не ждать сборку; ход - tools/deploy.sh status
tools/deploy.sh status      # журнал сборки, контейнер, ответ /api/health
```

Скрипт кладёт код в `/opt/bounce/src`, собирает образ на сервере в фоне (журнал -
`/opt/bounce/deploy.log`), ставит сайт в `/etc/caddy/sites/bounce.caddy` и проверяет
`/api/health`. Настройки - в `.env` (`DEPLOY_HOST`, `DEPLOY_DOMAIN`, ключ ssh).

После первой выкладки - главный пользователь на сервере (остальных он заводит в приложении):

```
tools/deploy.sh admin <логин> <пароль> <имя>
```

Та же команда возвращает главному права и задаёт новый пароль, если он потерян.

Автоматических резервных копий нет. Главный пользователь собирает копию в приложении (раздел
"Резервная копия"), скачивает её себе и при необходимости восстанавливает из файла; на сервере
в `/opt/bounce/pb_data/backups` остаётся только последняя собранная или загруженная копия.
